# Исправление: Спам ошибками предохранителя каждые 5 минут

## Проблема

При стабильном сбое API Wildberries (431 книга без остатков) предохранитель срабатывал **каждые 5 минут** и писал в журнал одну и ту же ошибку. Результат — "огромная красная ебень на весь экран" в логах.

## Почему это происходило

1. **Слежение за остатками работает каждые 5 минут** (настройка `stock_watch_interval_minutes`)
2. **Сбой WB может длиться часами** — API стабильно возвращает некорректные данные
3. **Каждый проход писал в журнал** — без проверки, была ли такая же ошибка недавно
4. **Scheduler дублировал в логи** — `logger.warning()` при каждом срабатывании

Итого: при 2-часовом сбое WB → 24 срабатывания → 48 записей (журнал БД + логи сервера).

## Что исправлено

### 1. Дедупликация в `catalog_sync.py`

Добавлена проверка: если такое же срабатывание было меньше 30 минут назад — молчим.

```python
# catalog_sync.py:589-602
# Проверяем последнее срабатывание: если то же количество книг и недавно
# (< 30 минут), молчим. Сбой WB может длиться часами — не нужно забивать
# журнал сотнями одинаковых записей.
from datetime import timedelta
recent_halt = db.scalar(
    select(SyncLog).where(
        SyncLog.marketplace == marketplace,
        SyncLog.action == "watch_stocks",
        SyncLog.ok == False,
        SyncLog.message.like(f"%ОСТАНОВЛЕНО: у {len(candidates)} из%"),
        SyncLog.created_at >= utcnow() - timedelta(minutes=30)
    ).order_by(desc(SyncLog.created_at)).limit(1)
)

if not recent_halt:
    # Первое срабатывание или изменился масштаб — пишем полный отчёт
    _log(db, marketplace=marketplace, action="watch_stocks", ok=False, ...)
    _log(db, marketplace=marketplace, action="watch_stocks_halted_full", ok=False, ...)
# Если недавно уже было — молчим, не спамим в журнал
```

**Логика:**
- Первое срабатывание → пишем в журнал с полным списком книг
- Повторное в течение 30 минут с тем же числом книг → молчим
- Через 30 минут → снова пишем (напоминание, что проблема не ушла)
- Изменилось количество книг → пишем (ситуация изменилась)

### 2. Убран дубль в `scheduler.py`

Раньше:
```python
if halted:
    logger.warning("Слежение за остатками остановлено: %s книг", halted)
```

Теперь:
```python
if halted:
    # Дедупликация уже есть в catalog_sync.watch_stocks — он пишет
    # в журнал только при первом срабатывании. Молчим в логах.
    pass
```

**Результат:** Запись в журнале БД есть (для UI), но в логи сервера не пишем каждые 5 минут.

## Логика книг только на WB

**Вопрос:** Зачем трогать книги, которые только на WB?

**Ответ:** Не трогаем!

1. **При срабатывании предохранителя** → `_cross_withdraw` НЕ вызывается → книги не тронуты
2. **При реальной продаже** (< 10 книг) → `_cross_withdraw` вызывается, но:
   - Лот WB помечается `WITHDRAWN`
   - Цикл `for other_listing in book.listings` не находит лоты других площадок
   - Кросс-снятие не происходит
   - Книга просто помечается проданной на WB

**Кросс-снятие работает только когда есть что снимать** — если книга только на WB, другие площадки не трогаются.

## Как проверить, что работает

### 1. Дождаться следующего срабатывания

При следующем сбое WB увидите:
- **Первый раз:** запись в журнале с полным списком
- **Повторы в течение 30 минут:** молчание
- **Через 30+ минут:** новая запись (если проблема не ушла)

### 2. Проверить журнал

```bash
.venv/bin/python scripts/halted_stocks_report.py --last 5
```

Увидите:
- Первое срабатывание в 22:45
- Следующее в 23:15 (через 30 минут)
- НЕТ записей в 22:50, 22:55, 23:00, 23:05, 23:10

### 3. Логи сервера

## Если хотите изменить интервал молчания

По умолчанию 30 минут. Чтобы изменить:

```python
# catalog_sync.py:589
SyncLog.created_at >= utcnow() - timedelta(minutes=30)  # было 30
                                                         # ↓
SyncLog.created_at >= utcnow() - timedelta(minutes=60)  # стало 60
```

## Когда НЕ молчим

1. **Первое срабатывание** — нужно показать проблему
2. **Прошло > 30 минут** — напоминание, что проблема не решилась
3. **Изменилось количество книг** — ситуация изменилась, нужна новая запись

## Итого

✅ **Убран спам в журнал** — дедупликация повторяющихся срабатываний  
✅ **Убран спам в логи сервера** — scheduler больше не пишет warning  
✅ **Первое срабатывание видно** — попадает в журнал с полным списком  
✅ **Напоминания каждые 30 минут** — если проблема не решилась  
✅ **Книги только на WB** — не трогаются при кросс-снятии  

**Красная ебень каждые 5 минут исчезла.** Теперь одно срабатывание → одна запись (с повтором через 30 минут, если проблема не ушла).
