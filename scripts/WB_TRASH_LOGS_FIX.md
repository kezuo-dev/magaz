# Исправление логов удаления в корзину WB

## Проблема

Логи вводили в заблуждение:

```
01:58:15  Очистка корзины WB: обработано 28, удалено 0, отложено 28
01:58:15  Лимит WB: остановились после 0 удалений, отложено 28 карточек
```

**Непонятно:**
- "Обработано 28" — но ничего не удалено?
- Две записи об одном событии (дублирование)
- Лог "остановились после 0 удалений" не несёт смысла

## Причина

### 1. "Обработано" считало кандидатов, а не реально удалённое

```python
# БЫЛО
processed = len(to_delete)  # все кандидаты
return {"processed": processed, "deleted": deleted, "failed": failed}

# Когда лимит 429 на первой пачке:
# processed = 28 (все кандидаты)
# deleted = 0 (ничего не удалили)
# → "обработано 28, удалено 0" — непонятно!
```

**"Обработано"** должно означать: **отправлено в API** (удалено успешно + failed).

### 2. Дублирование логов

Писалось две записи:
1. При лимите 429: "Лимит WB: остановились..."
2. В конце: "Очистка корзины WB: обработано..."

### 3. Непонятное сообщение при лимите

```
Лимит WB: остановились после 0 удалений, отложено 28 карточек
```

Если `deleted=0`, зачем писать "остановились после 0"? Это как "не начали и остановились".

## Исправление

### 1. "Обработано" = реально отправлено в API

```python
# СТАЛО
processed = deleted + failed  # только то, что отправили в API
return {"processed": processed, "deleted": deleted, "failed": failed, "skipped": skipped}
```

Теперь:
- `processed` = сколько карточек реально попробовали удалить через API
- `deleted` = удалилось успешно
- `failed` = API вернул ошибку (не 429)
- `skipped` = отложено из-за лимита 429

### 2. Одна итоговая запись вместо двух

```python
# БЫЛО
if "429" in err:
    _log(db, message=f"Лимит WB: остановились после {deleted} удалений...")
    break

if verbose or deleted or failed or skipped:
    _log(db, message=f"Очистка корзины WB: обработано {len(to_delete)}...")
```

```python
# СТАЛО
if "429" in err:
    skipped = len(to_delete) - i
    _log(db, message=f"Лимит WB при удалении в корзину: остановились, отложено {skipped} карточек")
    break

# Одна итоговая запись с компактным форматом
msg_parts = []
if deleted:
    msg_parts.append(f"удалено {deleted}")
if failed:
    msg_parts.append(f"не удалось {failed}")
if skipped:
    msg_parts.append(f"отложено {skipped} (лимит WB)")

message = f"Очистка корзины WB: {', '.join(msg_parts)}"
_log(db, action="wb_trash", ok=(failed == 0), message=message)
```

### 3. Компактные сообщения

**Было:**
```
Очистка корзины WB: обработано 28, удалено 0, отложено 28
Лимит WB: остановились после 0 удалений, отложено 28 карточек на следующий запуск
```

**Стало:**
```
Лимит WB при удалении в корзину: остановились, отложено 28 карточек
Очистка корзины WB: отложено 28 (лимит WB)
```

Или когда что-то удалилось:
```
Лимит WB при удалении в корзину: остановились, отложено 20 карточек
Очистка корзины WB: удалено 8, отложено 20 (лимит WB)
```

```
Лимит WB при удалении в корзину: остановились, отложено 28 карточек
```

```
Очистка корзины WB: удалено 8, отложено 20 (лимит WB)
```

```

```

```
Очистка корзины WB: удалено 10, не удалось 3, отложено 15 (лимит WB)
```

## Изменённые файлы

- `app/wb_trash.py` — новая логика "обработано", компактные сообщения
- `app/scheduler.py` — обновлён вывод в server log

## Итого

✅ "Обработано" теперь означает реально отправленное в API  
✅ Одна итоговая запись вместо двух  
✅ Компактный формат: только то, что произошло  
✅ Понятные сообщения при лимите 429  

Логи теперь читаются легко и не дублируются.
