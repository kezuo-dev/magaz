# Исправление фильтра предохранителя массового снятия

## Проблема

Предохранитель срабатывал на 441 книгу, но среди них были:

1. **Книги ТОЛЬКО на WB** — их вообще не нужно трогать, кросс-снимать не с чего
2. **Книги уже снятые/проданные** (статус != PUBLISHED) — уже обработаны ранее
3. **Книги без активных лотов на других площадках** — кросс-снятие бессмысленно

Результат: **ложные срабатывания предохранителя** на книгах, которые система и так бы не тронула.

## Пример из логов

```
02:08:01  Слежение за остатками ОСТАНОВЛЕНО: у 441 из 28856 книг
          пррпр ДУБЛЬ2-313, гтингтиЛ-542, трогооТ-366...
```

Пользователь проверил вручную:
- Многие книги **ТОЛЬКО на WB** (нет на Ozon)
- Некоторые уже **полностью отработаны** (статус SOLD/WITHDRAWN)
- Часть книг **вообще нигде нет** (удалены)

**Проблема:** предохранитель считал ВСЁ подряд, не фильтруя то, что реально нужно снимать.

## Причина

### Старый код (строки 546-566)

```python
candidates: list[tuple[Listing, Book, str]] = []
for listing in keyed:
    book = listing.book
    if book is None:
        continue
    if book.id in seen_books:
        continue
    
    # Проверяем остаток
    amount = stocks.get(listing.stock_key)
    if amount is None or amount <= 0:
        candidates.append((listing, book, reason))  # ← ДОБАВЛЯЕМ ВСЁ ПОДРЯД
        seen_books.add(book.id)
```

**Что не учитывалось:**
- ❌ Статус книги (уже снятая попадала в кандидаты)
- ❌ Наличие лотов на других площадках (книги только на WB попадали)

### Что происходило при сбое WB

```
WB вернул 0 остатков для 441 книги

Из них:
- 300 книг ТОЛЬКО на WB (кросс-снимать не с чего)
- 50 книг статус SOLD (уже сняты ранее)
- 91 книга на WB + Ozon (реально нужно кросс-снимать)

Предохранитель: 441 > 10 → HALT!

Реально опасных: 91 < 10 → можно было обработать спокойно
```

**Предохранитель остановил систему на книгах, которые она и так бы не тронула.**

## Исправление

### Новый код (строки 543-586)

```python
candidates: list[tuple[Listing, Book, str]] = []
for listing in keyed:
    book = listing.book
    if book is None:
        continue
    if book.id in seen_books:
        continue

    # ✅ ФИЛЬТР 1: Только активные книги (PUBLISHED)
    if book.status != BookStatus.PUBLISHED:
        continue

    # ✅ ФИЛЬТР 2: Только книги с лотами на ДРУГИХ площадках
    has_other_listings = any(
        other.marketplace != marketplace and other.status == ListingStatus.PUBLISHED
        for other in book.listings
    )
    if not has_other_listings:
        continue

    # Проверяем остаток
    amount = stocks.get(listing.stock_key)
    if amount is None or amount <= 0:
        candidates.append((listing, book, reason))  # ← ДОБАВЛЯЕМ ТОЛЬКО НУЖНОЕ
        seen_books.add(book.id)
```

### Что изменилось

**Фильтр 1: `book.status != BookStatus.PUBLISHED`**
- Пропускаем книги со статусом SOLD, WITHDRAWN, DELETED
- Они уже обработаны ранее, не должны попадать в кандидаты

**Фильтр 2: `has_other_listings`**
- Проверяем: есть ли активные лоты на ДРУГИХ площадках?
- Если книга ТОЛЬКО на WB → пропускаем (кросс-снимать не с чего)
- Если книга на WB + Ozon → добавляем в кандидаты

## Как работает теперь

### Сценарий 1: Сбой WB (441 книга с нулевым остатком)

```
До исправления:
  candidates = 441 (все подряд)
  441 > 10 → HALT!

После исправления:
  Фильтр 1: Убрали 50 книг со статусом != PUBLISHED
  Фильтр 2: Убрали 300 книг только на WB
  candidates = 91 (реально требуют кросс-снятия)
  91 > 10 → HALT! (правильно)
```

Предохранитель **всё ещё сработает**, но на правильном числе (91, а не 441).

### Сценарий 2: Реальные продажи 5 книг (все на WB + Ozon)

```
До исправления:
  candidates = 5
  5 <= 10 → обработать

После исправления:
  Фильтр 1: Все PUBLISHED ✓
  Фильтр 2: Все на WB + Ozon ✓
  candidates = 5
  5 <= 10 → обработать
```

Работает так же.

### Сценарий 3: Сбой WB на книгах ТОЛЬКО на WB (300 книг)

```
До исправления:
  candidates = 300 (книги только на WB)
  300 > 10 → HALT!
  Ошибка: книги и так не трогаем, зачем останавливать?

После исправления:
  Фильтр 2: Убрали все 300 (нет лотов на других площадках)
  candidates = 0
  0 <= 10 → ничего не делать (молчать)
```

Теперь **НЕ останавливаемся** на книгах, которые не требуют действий.

### Сценарий 4: Смешанный сбой (200 только WB + 15 WB+Ozon)

```
До исправления:
  candidates = 215
  215 > 10 → HALT!

После исправления:
  Фильтр 2: Убрали 200 (только WB)
  candidates = 15 (WB + Ozon)
  15 > 10 → HALT! (правильно — 15 кросс-снятий это сбой)
```

Предохранитель срабатывает **на правильной метрике**.

## Преимущества

### 1. Точность предохранителя

**Было:** Срабатывает на всех книгах с нулевым остатком  
**Стало:** Срабатывает только на книгах, требующих кросс-снятия

### 2. Меньше ложных срабатываний

Сбой WB на книгах только на WB больше не останавливает систему.

### 3. Понятные логи

Если предохранитель сработал — в списке **только книги, которые реально хотели снять**.

### 4. Не трогаем лишнее

Книги только на одной площадке никогда не попадут в кандидаты → никогда не снимутся по ошибке.

## Влияние на порог MAX_WATCH_REMOVALS_PER_RUN = 10

Порог остался тем же (10 книг), но теперь считаются **только книги, требующие кросс-снятия**.

**Раньше:**
- 10 книг = любые книги с нулевым остатком (включая только на WB)

**Теперь:**
- 10 книг = только книги на нескольких площадках (реально опасные)

**Вывод:** Порог стал строже по смыслу, но адекватнее. Если за 5 минут 10+ книг нужно кросс-снять — это действительно подозрительно.

## Что будет при следующем сбое WB

```
WB вернул 0 для 441 книги (как в вашем случае)

Фильтр 1: Убрали уже снятые
Фильтр 2: Убрали книги только на WB

Осталось: 50-100 книг на WB + Ozon

Если 50-100 > 10:
  → Предохранитель сработает (правильно)
  → В логах будут только книги WB + Ozon
  → Пользователь увидит реальный масштаб проблемы

Если < 10:
  → Обработаем спокойно (кросс-снимем)
```
