## Вердикт: Система работает правильно

### Причины отсутствия записей

**1. Backlog = 0 — все книги удалены**

После 09:17:29 корзина WB обработала все снятые книги. Больше удалять нечего.

**2. Автозапуск молчит, когда делать нечего**

```python
# scheduler.py
result = move_withdrawn_to_trash(db, limit=None, verbose=False)
#                                                ^^^^^^^^^^^
#                          Молчим, когда нечего удалять
```

**3. Логика verbose=False**

```python
# wb_trash.py
if not books:
    if verbose:  # ← False при автозапуске
        _log(db, message="снятых книг для удаления нет")
    return  # ← Молча выходим
```

## Как работает система

### Когда ЕСТЬ что удалять

```
10:00 — Scheduler запустился
        → move_withdrawn_to_trash(db, verbose=False)
        → Нашли 28 книг
        → Удалили 28
        → _log: "удалено 28" ✓ записано
```

### Когда НЕЧЕГО удалять

```
10:10 — Scheduler запустился
        → move_withdrawn_to_trash(db, verbose=False)
        → books = [] (пусто)
        → if not books: return
        → НИЧЕГО не записано (verbose=False)
```

**Это правильно!** Иначе каждые 10 минут в журнал падала бы запись "нечего удалять" — 144 записи в день, в которых тонут настоящие ошибки.

## Когда появятся новые записи

Записи появятся, когда:
1. **Кто-то купит книгу** → статус SOLD → появится в корзине
2. **Вы снимете книгу вручную** → статус WITHDRAWN → появится в корзине
3. **Синхронизация снимет книгу** → то же самое

## Проверка работы

### Через 10 минут после продажи

```
Продажа на WB → sync.py → статус SOLD → 
(через 10 мин) wb_trash → найдёт книгу → удалит → запись в журнал
```

### SQL проверка backlog

```sql
-- Есть ли книги для удаления?
SELECT COUNT(*) 
FROM books b
JOIN listings l ON l.book_id = b.id
WHERE b.status IN ('sold', 'withdrawn')
  AND l.marketplace = 'wildberries'
  AND l.external_id IS NOT NULL;  -- есть nmID

-- Если 0 → система справилась
-- Если > 0 → будут обработаны в ближайшие 10 минут
```
